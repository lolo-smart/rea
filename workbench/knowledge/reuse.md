# 跨工程使用与经验回写

## 调用现有工作台

从任意工程调用本机已部署的独立工作台：

```powershell
& E:\REA\workbench\rea.ps1 --version
& E:\REA\workbench\rea.ps1 capabilities --json
& E:\REA\workbench\Verify-Workbench.ps1
```

部署到其他电脑时把路径换成实际克隆目录；安装过程见[工作台说明](../README.zh-CN.txt)。源码目录和运行包是不同概念，修改源码后不会自动改变已固定的 npm MCP 运行包。

CLI 示例不会自动把 REA 注册到其他聊天。MCP 必须由相应客户端加载注册；注册路径变化后重新生成 setup 计划。不要复制某台机器的 providers、密钥或整个客户端配置到仓库。

IL2CPP 可选验证：

```powershell
& E:\REA\workbench\Verify-Workbench.ps1 -MetadataPath C:\samples\global-metadata.dat
# 仅在确认属于同一构建后提供匹配原生库：
& E:\REA\workbench\Verify-Workbench.ps1 -MetadataPath C:\samples\global-metadata.dat -BinaryPath C:\samples\libil2cpp.so
```

这只提出对应检查；本库的历史元数据案例没有验证 native linking，不能把此示例当成已通过。

## 新任务的最小交接

1. 先读本库能力、相关案例与经验，再定义具体问题，例如某个技能的触发与数值、某贴图的 UV/混合，避免直接无范围地“恢复全部”。
2. 确认输入版本、架构、摘要、原件位置、派生产物与实验副本；不要混入其他包版本的地址或资源。
3. 优先回答问题的最小工具；源码普通架构分析可直接读源码，不必启动完整 REA 流程。
4. 保存完整 Evidence 到工程自己的忽略目录，交付摘要按需分页。需要关闭会话时先导出所需资料，记录清理结果。
5. 将实现修订与检查逐项关联，注明静态、运行、程序输入、人工操作、成品、手机及辅助条件的真实覆盖。
6. 收尾按模板写一条可复用经验；保留失败原因、实际修正、执行证据、限制和尚未验证项。

可在其他工程的任务说明中引用：

> 本任务使用独立 REA 工作台；先读其 workbench/knowledge 的能力范围和相关经验。样本与完整证据留本工程本地。结束后输出可脱敏的经验草稿及本地来源，区分 REA 直接结果、辅助工具和重建实现；不自动上传第三方资源或私有数据。

这段是可选交接文本，本次没有自动修改其他工程 AGENTS、安装技能、创建新聊天或启用后台采集。

## 回写到此仓库

将通用结论放在 `workbench/knowledge/`：在 `cases.json` 增补案例，必要时修改案例与经验表。公开版本引用案例 ID；私有原始路径、摘要、证据 ID 和本地验证记录保存在忽略目录的来源索引中。

发布前检查所选文件及 diff，确保没有日志、样本、解包源码、资源、安装包、账号、密钥、服务地址或机器配置。只提交审阅过的文档/通用脚本，接在远端最新父提交之后。提交完成后核对远端 SHA 与文件内容；网络失败则保留本地草稿并如实说明。

经验更新需要真实读取新来源；不能因为新聊天宣称完成，就自动把旧未验证项标成通过。材料撤销、用户反馈或版本变化要更新相应结论。
