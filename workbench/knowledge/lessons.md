# 经验与纠正

来源类别为 C01—C04，见[案例](project-cases.md)。这些是工程积累的方法，不是本次重新运行通过的测试清单。

| ID / 来源 | 经验 | 下次执行方式 |
| --- | --- | --- |
| L01 / C01,C04 | 同名包和同名原生库未必同构建 | 固定输入版本、摘要、架构与文件集合；更新包独立建证据链 |
| L02 / C01,C03 | 容器清单、元数据、源码、行为是不同产物 | 给每项主张注明证据种类；文件恢复百分比不得外推为行为等价 |
| L03 / C01 | 大 DummyDll 不宜直接全量输出 | 优先精确查询/分页；必要投影保留转换说明和输入/输出摘要，声明 token 与坐标变化 |
| L04 / C01 | 空方法和声明不提供战斗算法 | 追到匹配 native 方法及其配置，再验证触发、数值与表现；未知保留未知 |
| L05 / C02 | 编译修复要回到原 CIL 与依赖版本 | 保留方法体，校正声明与程序集归属；避免同时保留同名源码与玩家 DLL |
| L06 / C02 | GUID 审计覆盖有限 | 分别核对 GUID、fileID、依赖、动态加载和成品运行，不把零缺失 GUID 当全通过 |
| L07 / C02,C03 | Shader 编译和孤立预览不证明整机画面 | 验证实际相机堆栈、混合/透明、色彩空间、HDR、UV、批处理、DPI 和顶点变换 |
| L08 / C02 | 材质面板参数不保证 Shader 使用它 | 查活动 Shader 执行路径；用同网格/骨架和固定姿态做 A/B，检查真实光照 |
| L09 / C02 | 同名骨骼不意味着动画适配 | 保留人体比例；核对绑定姿态、关节范围、肢体长度、蒙皮及座椅/杯子/方向盘接触 |
| L10 / C02 | 黑色三角形不必然是网格破洞 | 先用中性材质隔离 UV/材质，再查边界和退化面；不要凭截图盲改拓扑 |
| L11 / C01,C02 | 测试捷径可能绕过真实入口 | 区分手动赋皮肤、直接回调、注入结算和正常生成/点击/通关；成品走正常路径复核 |
| L12 / C02 | 双端同步要验真正的共房与隔离 | 普通双开、正常身份、创建/加入、断线重连；既验同房收敛，也验不同房不串数据 |
| L13 / C02 | 网络延迟与渲染卡顿不能混为一谈 | 分开记录发送、调度、接收、插值与帧耗时；跨进程先对齐时钟，不比较任意 Stopwatch epoch |
| L14 / C03 | 原始包、实验副本、存档须隔离 | 原件只读；修改有差异和版本；测试独立存档并验证正式存档未变 |
| L15 / C03 | 模块正确不等于生产调用正确 | 覆盖实际 Image/Canvas 与批处理；程序输入要经过生产桥，不以直接规则调用代替 |
| L16 / C03 | 提前写 passed 不证明退出完成 | 结合进程退出码、完整日志、存档读回和资源清理；程序事件不冒充物理设备验收 |
| L17 / C04 | 安装器与保护外壳可能挡住目标事实 | 先区分每层文件身份；只能对已检查层下结论，未见导入/字符串不等于功能不存在 |
| L18 / 跨工程 | 客户端超时与 provider 超时是不同边界 | 先查错误归属和存活工作；依返回的恢复指引调整对应预算，不原样重复启动重任务 |
| L19 / 工作台 | 工具目录对齐不等于引擎/目标支持 | 分别记录运行包、技能、已加载 MCP、provider 启动条件和目标接纳结果 |
| L20 / 工作台 | 网络失败不能冒充源码同步成功 | 记录本地 HEAD 与远端 HEAD；更新以实读的远端父提交为基线，推送后再次核对 |
| L21 / aircraft | 资源加载键可能忽略扩展名 | 按实际索引规则检查名称唯一性；改名保持 GUID，避免同 stem 的图片/材质碰撞 |

每条记录都应保留失败背景和适用范围。用户指出的画面/操作差异应撤销相应的整体完成结论，同时保留仍然有效的局部测试事实；不能用旧报告覆盖新反馈。

性能结论必须来自等价任务的测量。输出少、工具多、无异常或已缓存，都不是单独的性能证明。历史固定路线数据也不能扩展为公网、全部设备或整局稳定性。
